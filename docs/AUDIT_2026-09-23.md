# Integration audit — 23 September 2026

The native two-way candidate was integrated as **summclust 5.1.1**, a development release suitable for co-author review within the documented scope. No Monte Carlo results were regenerated as part of this integration.

## Provenance

- Destination base: commit `bfac520e8716941a960a39cb434289c66e4b1e8b`, version 4.22.
- Supplied source: the local research folder named `summcluster_twoway`, version 5.1.0 dated 23 August 2026. Its original `summclust.ado` SHA256 is `0A54827F182E40BF6C388F79793C567970D2BFAEA4E4B2F68ABB2EC5EB4EB2F5`.
- Only release code, help, package metadata, documentation, and certification scripts were integrated. Research data, old benchmark outputs, logs, and archives were excluded. The source research folder was unchanged.

## Findings addressed

The upstream candidate passed its four original certification suites before changes. Additional audit cases found that subsequent fixed-effect coefficient labels did not match the omitted category, fixed-name native Mata arrays overwrote caller objects, and a cluster deletion that destroyed focal identification could still produce apparently valid CV3 inference. These are corrected and independently tested in 5.1.1.

The integration also preserves the precision of double outcomes in the one-way path, counts rank after within transformation in absorbed-model CV1 corrections, rejects nonpositive residual degrees of freedom, and reports explicit maximum-component ties. The optimized source already fixes the old partial-leverage calculation and the one-way fixed-effect CV3J crash.

## Validation

Executed using StataNow/SE 18.5, Windows x86-64, revision 26 February 2025. All six suites passed:

| Suite | Principal coverage |
| --- | --- |
| `certify_summclust.do` | One-way CV1/CV3/CV3J, leverage, FE/absorb handling, options, error cases, graphs |
| `certify_summclust_twoway.do` | Direct CV1 and deletion-based CV3 references; nested, coincident, unbalanced and string clusters; FE, absorption, rank and negative conventional variances |
| `certify_summclust_twoway_api.do` | Return contract, component aliases, inference, labels, tables and sample restrictions |
| `certify_twowayjack_delegate.do` | Thin wrapper agreement with the native two-way command |
| `certify_integration.do` | 160 independent FE deletion refits, exact balanced partial leverage, precision, labels, object preservation, identification failures, ties and absorbed degrees of freedom |
| `verify_net_install_twoway.do` | Local package installation into an isolated PLUS tree, then loading both commands away from the source directory |

The independent FE test uses G=H=8 with one and 25 observations per cell. It compares every G, H, and intersection deletion to a fresh Stata regression, with absolute slope and focal covariance tolerance 1e-10; balanced partial leverage is 1/8 to tolerance 1e-12. Native CV1 components also match direct clustered Stata regressions. These are deterministic validation designs, not additional Monte Carlo replications.

The original near-collinearity test accepted any nonmissing standard error with `z=x+1e-8*noise`. It now expects error 498 because that system cannot resolve the focal slope numerically. A resolved `z=x+.1*noise` case remains required to succeed. This is an intentional contract correction, not a waived failure.

## Limits and retained behavior

- Two-way CV3 is uncentered. Centered two-way CV3J is not exposed; `jackknife` returns error 198 in two-way mode.
- Two-way absorption is valid only for groups nested in both cluster dimensions. Crossed FE use explicit indicators through `fevar()`.
- The focal estimability check uses the focal row of `invsym(X'X)*(X'X)` and a 1e-7 tolerance. Very ill-conditioned or poorly scaled models may be rejected. The audit does not certify all numerical configurations.
- The conventional covariance may be indefinite. The coefficient-specific maximum is not a full covariance estimator for joint tests.
- One-way warning/drop rules retain the old near-zero-coefficient proxy, even when `rankcheck` also returns actual rank diagnostics. One-way working Mata variables remain part of the legacy behavior; the object-isolation fix applies to the native two-way path.
- Stata 13 compatibility is declared in the source but was not tested on a Stata 13 installation. No new performance benchmark or cross-platform execution was part of this audit.

The earlier pilot used version **4.22** through three separate one-way calls, for G, H, and their intersections. Its custom `negative_dependence_pilot/programs.do` assembled the inclusion-exclusion and scalar-max results. It did not invoke native `cluster(g h)` or an existing multi-jack estimator.

The exact 4.22 ado/help files and license were frozen under the pilot's `vendor/summclust_4_22` directory before this upgrade. Its configuration now selects that copy.
